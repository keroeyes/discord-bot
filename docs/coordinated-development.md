# 역할 분담 개발 실행 절차

## 적용 범위와 현재 상태

개발 작업을 총괄·분석·구현·검수로 나누기 위한 실행 양식입니다.
[AGENTS.md](../AGENTS.md)와 [CONSTRAINTS.md](../CONSTRAINTS.md)를 먼저 따릅니다.
작은 수정은 한 사람이 처리하고 마지막에 별도 검수 단계를 수행합니다.
독립적인 조사나 구현이 둘 이상인 큰 작업에만 담당자를 나눕니다.
에이전트 실행 기능과 권한이 실제 제공되는 환경에서만 별도 에이전트를 배정하며,
지원되지 않으면 총괄이 같은 양식으로 순차 처리하고 그 사실을 보고합니다.

이 문서는 자동 배정기·파일 잠금·자동 reviewer를 설치하지 않습니다.
현재 devtools/autopatcher.py는 단일 작업의 생성→격리 테스트→초안 PR 흐름입니다.
동시 프로세스 잠금이 없으므로 자동패치 작업기를 여러 개 동시에 실행하지 않습니다.
일반 Discord 응답의 모델 호출·비용·권한은 변경하지 않습니다.

## 1. 총괄이 작업 범위 확정

아래 양식을 작업 설명 또는 PR 본문에 작성합니다. 비밀이나 실제 사용자 입력은 넣지 않습니다.

```text
목표:
확인한 기준 커밋:
관측한 문제 또는 새 기능 계약:
합성 재현 방법:
수정할 경로:
수정 제외 경로:
완료 기준:
실행할 검사:
미확인 사항:
되돌리기 방법:
```

코드 변경 전 완료 기준을 정합니다. 근거 부족은 오류 재현으로 취급하지 않습니다.
큰 작업도 첫 배정은 유용한 독립 작업 최대 3개로 제한합니다.

## 2. 역할과 파일 소유권 배정

| 역할 | 책임 | 필수 인계 |
| --- | --- | --- |
| 총괄 | 범위·작업 의존성·파일 소유권·통합·최종 보고 | 기준 커밋, 완료 기준, 작업 배정표 |
| 분석 | 합성 사례 재현, 요청 경로와 원인 확인 | 파일/심볼, 관측 결과, 가설과 미확인 구분 |
| 구현 | 확인된 원인 수정, 관련 회귀 검사 | 후보 커밋, diff, 검사 명령·결과 |
| 검수 | 최종 diff와 요구사항 대조, 필요한 사례 재현 | 요구사항별 근거, 결함, 미시험 항목 |

```text
작업 ID | 담당 | 기준 커밋 | 읽기 범위 | 수정 소유 경로 | 선행 작업 | 완료 기준 | 상태
A | 분석 | ... | ... | 없음 | 없음 | ... | 준비
B | 구현 | ... | ... | ... | A | ... | 대기
C | 검수 | ... | ... | 없음 | B | ... | 대기
```

읽기 전용 조사는 병렬 진행할 수 있습니다. 같은 파일 수정은 직렬로 인계합니다.
담당별 격리 브랜치/작업 디렉터리를 사용하고 총괄이 diff를 순서대로 통합합니다.
범위가 겹치거나 기준 커밋이 바뀌면 먼저 배정표를 수정하고 영향을 다시 확인합니다.
담당자에게 병합·배포 권한이나 운영 인증정보를 추가로 주지 않습니다.

## 3. 결과 인계와 실패 처리

```text
작업 ID / 담당:
실제 확인한 revision 또는 후보 해시:
관측한 사실과 근거 파일/심볼:
변경 파일:
실행한 명령과 결과:
미실행·미확인:
다음 담당자가 확인할 항목:
```

담당자의 통과 보고와 총괄이 직접 확인한 근거를 구분합니다.
같은 실패가 새 근거 없이 두 번 반복되면 코드·환경·인증·권한·외부 서비스·정보 부족으로
분류하고 원인을 진단합니다. 무한 재시도나 새 유료 서비스로의 임의 전환은 하지 않습니다.
두 차례 검수로도 결론이 나지 않으면 근거 공백과 필요한 다음 조치를 명시합니다.

## 4. 최종 후보 검수

| 요구사항 | 최종 후보의 근거 | 확인 방법·결과 | 판정 |
| --- | --- | --- | --- |
| 원래 문제 해결 또는 새 계약 | 파일/심볼/후보 커밋 | 합성 재현 또는 계약 검사 | 확인/미확인/실패 |
| 기존 기능 호환 | 영향 경로 | 관련 회귀 검사 | 확인/미확인/실패 |
| 보안·개인정보 | 권한/로그/전송 경로 | 해당 변경이 있을 때 집중 검토 | 확인/미확인/실패/해당 없음 |
| 운영 반영 | 배포 커밋·실사용 결과 | 실제 관측이 있을 때만 기록 | 확인/미확인/해당 없음 |

변경에 맞는 AGENTS.md의 검사와 영향받는 CI를 사용합니다.
문서 변경은 내용·링크·최종 diff를 검수하고 런타임 테스트를 실행했다고 쓰지 않습니다.
구현자와 별도 에이전트를 쓰더라도 최종 후보를 직접 확인하지 않은 검수는 미확인입니다.
검수 후 파일이 바뀌면 영향받는 요구사항과 검사를 다시 확인합니다.
실패 항목은 수정 후 재검수하며, 미확인 항목을 통과로 바꾸지 않습니다.
해당 없음에는 이유를 적습니다.

## 5. PR과 완료 보고

```text
변경:
기준 / 최종 후보 커밋:
검증한 요구사항과 실제 근거:
남은 미확인:
소스 변경 / 로컬 검사 / CI / 요구사항 검수:
PR / 병합 / 배포 / 실사용 검증:
```

사용자 승인과 저장소 규칙에 따라 병합·배포합니다. 기존 명시 승인은 해당 범위에서 유지합니다.
초안 PR 생성이나 CI 통과를 배포·실사용 성공으로 보고하지 않습니다.
자동패치 PR도 이 절차로 검수하되 기존 두 번의 생성 호출 상한은 유지합니다.

## 적용 예: OCR 장애 조사

이것은 작업 분담 예시이며 현재 장애가 있다는 진단이 아닙니다.

- 분석: 합성 PDF로 Discord 접수→작업자→모델→결과 전송 중 실패 경계를 확인.
- 구현: 확인된 경계의 파일만 소유하고 수정, 관련 합성 회귀 검사 실행.
- 검수: 최종 커밋에서 원래 합성 사례·실패 처리·비공개 전송을 대조.
- 총괄: 통합 후 CI와 운영 증거를 별도로 기록. Windows/Discord 접근이 없으면 실사용 미검증.
