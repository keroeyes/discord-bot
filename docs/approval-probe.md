# 승인 보호 오프라인 실험

2026-11-06 주간 브리핑의 승인 재사용 방지 아이디어를 합성 입력으로 시험합니다.
운영 봇, Hindsight, Discord, E2B, 모델 API에는 연결하지 않습니다.
추가 의존성 없이 Python 3.11 이상 표준 라이브러리만 사용합니다.

```text
python devtools/approval_probe.py
python -m unittest discover -s devtools -p test_approval_probe.py -v
```

실제 삭제 대신 카운터만 증가합니다. 서버가 발급한 불투명 토큰을 합성 사용자,
작업 ID, 대상/상태 버전에 연결하고, 만료·재사용·다른 사용자·다른 작업·변경된
대상을 거부합니다. 같은 사용자/작업의 제안을 다시 만들면 이전 토큰을 폐기합니다.
동시 재전송은 프로세스 내 잠금으로 한 번만 처리합니다. 최대 128개 대기 제안,
TTL 기본 60초·상한 300초이며 만료 시각과 같아지는 순간부터 거부합니다.

## 적용 상태와 한계

- 독립 실험 코드와 회귀 테스트만 추가합니다. 운영 보호장치를 설치한 것이 아닙니다.
- 기존 `!기억삭제 확인`, 사용자/서버/채널 분리, 비공개 응답, 모델 설정은 그대로입니다.
- LangGraph 1.2.20의 내부 strict 설정은 도입하지 않고 기존 의존성을 유지합니다.
- 토큰은 인증된 사용자 신원을 대신하지 않습니다. 실제 연결 시 Discord 발신자 검증과
  서버/채널/리소스 범위 및 현재 상태 버전 검사가 별도로 필요합니다.
- 메모리 상태는 재시작 시 사라져 기존 승인은 거부됩니다. 다중 프로세스나 서버 간
  동시성, 외부 작업의 부분 성공/불명 결과를 처리하는 내구성 있는 실행 기록은 없습니다.
- 실제 외부 작업에서는 dispatch 기록과 백엔드 idempotency가 필요합니다. 이 잠금만으로
  네트워크 오류 후 정확히 한 번 실행을 보장하지 않습니다.
- 자연어 답변의 정확성이나 프롬프트 주입 방어율을 측정하는 벤치마크가 아닙니다.

향후 운영 연결은 별도 변경으로 검토합니다. 철회·만료·동시 실행·재시작·불명 결과와
정상 사용자 흐름을 모두 시험하고 나서 승인 UI와 실제 도구 사이에 연결해야 합니다.
